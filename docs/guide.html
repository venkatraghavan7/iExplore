A tester that plays your customers, learns, and tells you what matters

Claude drives a real browser as an invented customer on comparethemarket.com.au. It looks at the screen, clicks like a person, scans for accessibility failures, remembers what it has learned, and hands you a short, ranked list you can turn into ADO tickets.

The loop

Every session feeds the next. The knowledge base decides what to test, and the noise filters decide what a person sees.

One session, start to finish

About 10–15 minutes and one browser. Here's what happens in a run --dynamic.

  1. Pick a strategy.UCB1 bandit over past reward: explore, hotspot, fragility, recheck or journey. Explore fades as coverage rises.
  2. Design the person.Claude writes one realistic customer aimed at the weak spots, plus real conditions: typing speed, slow 3G, CPU throttling. Code then strips anything unsafe (real contact details, rego).
  3. Brief them.The prompt carries the persona, a charter (mission + oracles), untested branches, hot spots, known findings to re-check, and your team's quality bar.
  4. Explore by sight.Screenshot → Claude decides → click/type/scroll by pixel → screenshot. No selectors. Every page tagged ?automated-test=true.
  5. Watch underneath.Each step is recorded automatically (options shown, option clicked, time, errors), axe-core scans it, and failing or slow calls are logged.
  6. Write it up and learn.Report, findings, JUnit and screenshots are written; the knowledge base folds it in, scores the session, and updates triage and the digest.

Architecture

Claude decides, Playwright only executes, and nothing outside your accounts holds state.

What makes it smart

Five strategies, chosen by what has been paying off. Each session is scored, so the mix shifts on its own.

explore coverage

Takes branches never tried, or tried once, especially next to trouble. Fades as coverage rises.

hotspot depth

Digs into steps where findings cluster, varying inputs and order to find the trigger.

fragility stress

Fast typing, slow 3G, CPU throttling, double-clicks, back and refresh, applied for real.

recheck verify

Re-tests known findings. Candidates first, so one-offs are confirmed or dropped quickly.

journey fresh eyes

A new kind of customer end to end, judging copy, trust and flow.

reward = Σ severity(new findings) + 0.5 × new branches + 1 × new steps + 0.3 × confirmed + 0.5 × cleared

Fragility per step blends errors, drop-offs, erratic timing, flaky findings and failing calls. Weak pathways are branches tested once, or untested ones next to a hot or fragile step.

Signal over noise

Running often must not mean more tickets. Three filters stand between the bot and your team.

impact (0–100) = severity × reach × business risk × confidence × recurrence

Second sighting

New AI findings stay candidates until another session reproduces them. Blockers, axe results and human-observed issues skip this.

Weekly cap + lanes

At most 5 new findings a week reach triage, highest impact first, plus 1 reserved accessibility slot. The rest wait in the digest.

Quality bar

Your rejection reasons become rules in the prompt. Rejected issues never return unless they get worse.

Health check: the weekly digest shows the triage acceptance rate. Below 50% means the bot is too noisy and the quality bar or weights need tuning.

Guardrails on production

Enforced in code at the network layer, so they hold even if the model is misled by page text.

  • Stops before contact detailsNo name, email or phone submitted; no real quotes created unless you switch it on.
  • Payment, checkout, insurer hand-off blockedNavigation aborted; purchase APIs blocked.
  • Tagged traffic?automated-test=true plus the site's tag cookie on every step, verified.
  • No rego lookupsReal plates return real people's cars; the car is always chosen manually.
  • Fictional data onlyACMA fiction-range mobiles, example.com emails, commercial addresses.
  • Gentle by designHuman pace, at most one session an hour, budgets on turns, time and tokens.
  • Prompt-injection safePage text is content, never instructions.
  • Typed values never storedCoverage records field names and lengths, not what was typed.

Run it

The commands you'll actually use. Every run learns automatically unless you pass --no-learn.

# set up once (then npm run build so npx iexplore works)
npm ci && npx playwright install chromium && npm run build
# one dynamic session on prod (CI default)
npx iexplore run --dynamic
# force a strategy, or pick a fixed persona/charter
npx iexplore run --dynamic --strategy fragility
npx iexplore run --persona family-mei --charter results-scrutiny
# what has it learned? hot spots, gaps, journey map
npx iexplore coverage
# refresh triage register + pack + weekly digest
npx iexplore triage
# create ADO Bugs for rows you marked accept (dry run first)
npx iexplore ado-sync
npx iexplore ado-sync --apply
# plumbing test, no API calls, against the mock site
npm run mock &
npx iexplore run --target uat --dry-run

Ideas borrowed, in order

  1. builtImpact score, second sighting, weekly cap. Our answer to noise: severity × reach × business risk × confidence × recurrence, only reproduced findings, at most 5 a week.
  2. builtTeam quality bar (QA.tech). Rejected findings and their reasons go back into the prompt, so noise falls run by run.
  3. builtDeterministic accessibility scan (Siteimprove, TestMu). axe-core on every step under the AI's judgement, with a plain-English fix on each ticket.
  4. nextFindings to regression tests (KaneAI, Playwright Test Agents). Accepted findings become reviewed Playwright tests in the agentic harness.
  5. nextDeploy-triggered runs (PR-level agents). Run on each UAT deploy against the changed steps; alert only on new or returning issues.
  6. nextSession replay per finding (TestDriver). A short recording, not just a screenshot.
  7. laterPersonas on Figma before build (synthetic-user tools).

Build or buy

Buying gets dashboards, support and native-app coverage sooner. Building keeps the parts that matter most for CTM: production-safe rules tuned to our journeys, traffic tagging that analytics already filters, data and model calls inside our AWS accounts on Bedrock AU, tickets straight into ADO, and the adaptive core no vendor offers. The running cost is model tokens plus a small pod, and the code is ours to extend to pet, home and health.
